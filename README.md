Turn a single DeepSeek Harness session into a full game development studio.
**49 agents. 76 skills. One coordinated AI team.**

This is a **port of [Claude Code Game Studios](https://github.com/Donchitos/Claude-Code-Game-Studios) (CCGS)**
to DeepSeek Harness (DSH) — not a rewrite from scratch: the skills, agents, rules and docs come from
upstream (MIT); this repository provides the DSH-native runtime (Node hooks, skill generation,
machine-level install, plugin bridge).

| This repository | `deepseek-harness-game-studios` (DSGS) **v0.1.7** |
| Port strategy | Dual stack, one source: `.claude/` is the content source (upstream text, kept verbatim); `.dsh/**` is generated by `tools/build-dsh.mjs` |

Upstream targets Claude Code (`.claude/`, `.sh` hooks, `bash` one-liners, `@path` imports). None of that
runs under DSH (no `bash` tool, piped child processes are denied by the sandbox, `@path` is not expanded),
so instead of editing upstream content we generate a DSH-runnable equivalent and prove **no content loss**.

> This repository **is the plugin package**. The framework it installs is bundled under `payload/` — you never need to look at it.

## Install

### ① GUI

`Plugins` → `Add plugin` → paste `https://github.com/HYClub/deepseek-harness-game-studios` → **Install** → **restart `dsh web`**.

### ② Command line

```pwsh
dsh plugin --profile web add https://github.com/HYClub/deepseek-harness-game-studios
```

Then **restart `dsh web`**.

On first load the plugin installs the framework at machine level (`~/.dsh/dsgs` plus user-level
bootstrap skills). After that:

```
new working directory → new session → type /start
```

`/start` checks whether the workspace is initialised; if not it initialises it first, then walks you
through onboarding.

## What the plugin writes to your machine (and how to undo it)

| Path | What |
|---|---|
| `~/.dsh/dsgs/**` | framework payload (skills, agents, rules, hooks, tools, docs, instruction files) |
| `~/.dsh/skills/dsgs-init/SKILL.md`, `~/.dsh/skills/start/SKILL.md` | user-level bootstrap skills |

It never touches a project directory and never overwrites project files. To undo:

```pwsh
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh\dsgs"
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh\skills\dsgs-init","$env:USERPROFILE\.dsh\skills\start"
# then uninstall the plugin and restart dsh web
```

### ❌ Not implemented / no equivalent (with reasons and substitutes)

| Item | Status | Why | Substitute |
|---|---|---|---|
| Docked status bar above the composer | ❌ | DSH's client roster only lists `@deepseek-ai/*` packages (measured: 60+ entries, ours absent even with a `dsh.client` declaration) | `/statusline` skill + `node .dsh/statusline.mjs`; the runtime half (turns/tokens/cache/context %) is already covered by DSH's own status bar |
| Pre-action reminders on PreToolUse | ❌ | `tools/pre-execute` only carries `allow/deny/cancel/ask`; `additionalContexts` is read from the final tool result; `agent.inject()` mid-execution has no effect | `validate-commit` / `validate-push` are also registered on **PostToolUse** (reminder arrives after the action); set the plugin row `advisory: deny` to block before the action |
| 3 hook events cannot be triggered from a prompt | ⚠️ | `Notification`, `PreCompact`, `PostCompact` have no DSH event source | mapping implemented and unit-tested, verified at mount level only (live coverage 6/9) |
| Per-agent tool allowlists / agent auto-discovery | ❌ | DSH's `subagent` does not accept a per-agent tool set and has no agent registry | role cards + `toolFilter` / `persona` conventions |
| `@path` imports | ❌ | DSH does not expand imports | `.dsh/docs/studio-rules.md` (merged), read on demand |
| `!`cmd`` pre-execution lines | ❌ | DSH has no pre-execution | rewritten as a "prerequisite command" block the model runs itself |
| Byte-for-byte bash ↔ Node parity | ⚠️ | `python3` in this machine's Git Bash is a Store placeholder | 2 named SKIPs, 1 case byte-identical |

## Testing your own customizations

DSGS is a template you are meant to edit. `DSGS Skill Testing Framework/` is how you check that an
edited or newly written skill still holds up — a catalog of all skills and agents, per-category quality
rubrics, behavioral specs, and templates for writing specs of your own.

```
/skill-test static [name]     # structural linter
/skill-test category [name]   # category-specific quality rubric
/skill-test spec [name]       # behavioral spec assertions
/skill-test audit             # coverage report across skills and agents
/skill-improve [name]         # test-fix-retest loop; keeps or reverts on score change
```

It tests the *framework*, never your game — game tests live in `tests/`.
